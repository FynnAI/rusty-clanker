| A server's chunk-send radius for a connected client is decided server-side: the client's declared `ClientInformation.view_distance` states a request, and the server clamps that request to [2, min(its own configured view-distance setting, 32)], sends chunks at the clamped radius, gates entity-tracking range by the same value, and echoes the clamped radius back to the client in the Login packet. | The client's declared value is only one of three inputs, and the radius is decided server-side. `ChunkMap.getPlayerViewDistance` (ChunkMap.java:825-827) returns `Mth.clamp(player.requestedViewDistance(), 2, this.serverViewDistance)`; `ChunkMap.updateChunkTracking` (:1110-1119) builds the send set as `ChunkTrackingView.of(player.chunkPosition(), playerViewDistance)` from exactly that clamped value, and entity-tracking range uses it too (:1415-1416). `serverViewDistance` is the server's own `view-distance` property, default 10 (DedicatedServerProperties.java:104), itself re-clamped to [2,32] on ingestion (ChunkMap.setServerViewDistance, :813-822), pushed in via `DedicatedPlayerList` (DedicatedPlayerList.java:17) and `PlayerList.setViewDistance` (PlayerList.java:805-812). The server-side request value defaults to 2 (ServerPlayer.java:257) and is never validated or clamped on receipt (ServerGamePacketListenerImpl.java:2078-2081) — a bot that never sends ClientInformation therefore gets radius 2, not the server default.
